# Техническое задание и план выпуска Kitai

Цель первой версии — провести покупателя от запроса на русском языке до оригинальной карточки китайского поставщика. Готовность определяется отдельно для Android, сервера, перевода и каждой подключаемой площадки. Схема взаимодействия и общий HTTP-контракт приведены в [архитектуре](architecture.md).

## Пользовательские сценарии и критерии приёмки

| Сценарий | Наблюдаемый результат |
| --- | --- |
| Найти товар | Покупатель вводит запрос, выбирает площадки и получает список с названиями источников. При поиске по переводу доступен исходный запрос. Следующая страница дополняет список. Быстрая смена запроса оставляет на экране выдачу последнего запроса. |
| Отобрать предложения | Фильтры и сортировка учитывают активную площадку и выбранные единицы измерения. Межвалютная сортировка использует общий курс на одну дату. Фильтр с обязательным значением исключает предложения с неизвестным значением, остальные остаются доступны при сбросе фильтра. |
| Понять состояние каталога | Экран различает загрузку, совпадения, успешную пустую выдачу, частичную ошибку и отсутствие подключений. При отказе одного адаптера видны результаты остальных, источник сбоя и доступное действие. |
| Оценить предложение | В карточке видны оригинальное название, ссылка на площадку и дата наблюдения. При наличии данных показываются перевод, изображение, продавец, валюта, диапазон цен, минимальная партия и оценка в рублях с датой курса. Для оптовой цены указан применимый объём заказа. |
| Вернуться к товару | Избранное, просмотренная карточка и выбор для сравнения переживают завершение процесса и запуск без сети. Переключение закладки идемпотентно для пары «площадка, идентификатор». Удалить из избранного и очистить историю можно с устройства. |
| Сравнить предложения | Два предложения разных площадок с одинаковым локальным ID занимают разные колонки. Рядом показаны оригинальная цена, ориентир в рублях, минимальный заказ и продавец. Пропущенное значение отображается как неизвестное. |
| Перевести текст | Заказчик проверяет короткие карточки и поисковые запросы на направлениях RU → ZH, ZH → RU, EN → RU. Сохраняются смысл, числа, размеры и артикулы. При недоступном движке остаётся доступен оригинал. |
| Прочитать текст на изображении | На выбранном изображении пользователь видит исходный и переведённый текст в соответствующих областях. Поворот и масштабирование сохраняют привязку. При пустом распознавании показывается сообщение, при частичном переводе остаются прочитанные строки. |
| Открыть продавца | Проверенный адрес открывается в WebView. Пользователь видит домен, может вернуться к карточке или открыть разрешённую HTTPS-ссылку в системном браузере. Проверка адреса действует и после перенаправления. |
| Настроить приложение | Выбранные настройки сохраняются при перезапуске. Русские подписи, цены, формат дат и доступность основных действий проверены в светлой и тёмной темах и при увеличенном шрифте. |

## Последовательность реализации

| Этап | Работа и владельцы | Что открывает следующий этап |
| --- | --- | --- |
| 1. Проверка возможностей | Исследователь определяет официальную операцию каждой площадки, тип приложения, авторизацию, доказуемый ассортимент, лимиты и требования к использованию данных. | У каждой площадки есть ссылка на первичный источник и отдельный статус практического доступа. Неподтверждённые лимиты и коммерческие условия обозначены явно. |
| 2. Контракт | Архитектор, backend и Android согласуют идентификаторы, обязательные поля, формат денег и времени, причины отказа, пагинацию и поддерживаемые возможности. Дизайнер описывает состояния экранов. | Совместимый пример для Android и FastAPI. Есть случаи с частичной выдачей, недоступным источником, ценой по запросу и оптовой ценой. |
| 3. Первый сквозной сценарий | Android и backend реализуют поиск, открытие карточки и оригинала. Инженер перевода добавляет текстовый перевод и OCR. DevOps готовит воспроизводимую сборку. | Клиент установлен, обращается к тестовому серверу и показывает реальные состояния доступности. Владельцы проверили позитивную выдачу на контролируемых данных теста. |
| 4. Функции покупателя | Android реализует фильтры, сравнение, избранное, историю, настройки и перевод изображения. Backend подключает хранение, кеш, курсы и одобренные операции площадок. | Выполнены сценарии из таблицы на чистой установке и после повторного запуска. Сохранённые данные читаются при отключённой сети. |
| 5. Проверка релиз-кандидата | QA собирает результаты Android, сервера, перевода и живых интеграций. Визуальный проверяющий изучает снимки реального эмулятора, ревьюер и аудитор независимо проверяют код и границы доверия. | Критические дефекты P0/P1 закрыты и повторно проверены. Список доступных возможностей соответствует результатам прогонов. |
| 6. Выпуск и эксплуатация | DevOps и координатор сверяют бинарные артефакты, подписи, Compose-проект и восстановление. Технический писатель обновляет инструкцию установки, справочник API и ограничения версии. | Подготовлены версия, исходный коммит, проверенный комплект артефактов, отчёт и инструкция отката. |

## Владение файлами

| Область | Кто меняет файлы |
| --- | --- |
| `android/` | Android-разработчик. Изменения UI и инструментальных тестов согласуются с дизайнером и QA. |
| `backend/` | Backend-разработчик. `backend/kitai/translation/` закреплён за инженером перевода. |
| `.github/`, `deploy/` | DevOps. Тесты и миграции, затрагивающие API, согласуются с backend-разработчиком. |
| `docs/architecture/`, `docs/marketplaces/`, `docs/design/` | Архитектор, исследователь площадок и дизайнер соответственно. |
| `README.md`, `CHANGELOG.md`, `docs/guides/` | Технический писатель. Справочник API сверяется с FastAPI. |

Координатор согласует совместные файлы до редактирования. QA закрепляет место каждого набора тестов за владельцем модуля. Ревьюеры передают замечания с шагами воспроизведения, исправления вносит владелец файла.

## Проверка перед выпуском

| Область | Проверка | Подтверждение результата |
| --- | --- | --- |
| Площадки | Для каждой заявленной операции выполнить запрос с разрешённой учётной записью. Проверить название, цену с единицей, ссылку и пагинацию по ответу источника. Отдельно воспроизвести отсутствие доступа и ограничение частоты на контролируемых ответах. | Дата, площадка, операция, идентификатор запроса или обезличенный результат, фактически доступный ассортимент. При отсутствии ключей фиксируется «доступ не проверен» и сохраняется явный статус функции в приложении. |
| Перевод и курсы | Пройти три языковых направления, изображение с китайским текстом и единицами, пустое изображение, отсутствующую модель. Сверить CNY и USD с опубликованным XML, отдельно проверить тестовый номинал 10 и последний сохранённый курс. | Оригинал, ожидаемые числовые поля, фактический текст и границы, версия пакета, дата и источник курса. |
| Android | Проверить сборку, unit-тесты и пользовательские действия на эмуляторе. Просмотреть русский интерфейс на узком и широком экране, светлую/тёмную тему, увеличенный шрифт и фокус действий. | Результаты Gradle с версией SDK, снимки реальных экранов и вывод визуальной проверки Terra high при наличии эмулятора. |
| Backend и производительность | Поднять настоящий PostgreSQL и Redis. Проверить повторный запрос, сброс кеша, перезапуск, миграцию, отказ одного адаптера и запросы во время OCR. Измерить время первого ответа и повторного поиска, p95 задержки и пиковую память OCR на одинаковом наборе входов. | Тестовые результаты, конфигурация стенда, объём входных данных и измерения. Время ответа сравнивается с таймаутами клиента и согласованным бюджетом. |
| Код и безопасность | Отдельно проверить цены/валюты, параллельные запросы, обращение к секретам, доверенные переходы WebView, границы загрузок, доступ к БД и права CI. | Независимые отчёты ревьюера и аудитора. Для каждого P0/P1 сохранены исправление и результат повторной проверки. |
| Бинарный выпуск | Собрать APK и AAB одной версии, проверить подпись и ожидаемый сертификат. Установить APK на чистый эмулятор. Для обновления проверить установку поверх предыдущей совместимой версии с сохранением избранного. | Номер версии, коммит, SHA-256 артефактов, отпечаток сертификата и идентификатор успешно завершённой сборки CI. Приватный ключ хранит владелец релиза. |
| Synology | Проверить Compose, получить образ для архитектуры NAS по digest, поднять сервисы в отдельном проекте и проверить запрос Android через HTTPS. Восстановить резервную копию в отдельной БД и прочитать контрольную запись. | Версии DSM и Container Manager, digest, вывод проверки доступности, сверенные записи после восстановления и сведения об откате. |

Для установки APK вне магазина важна подпись ожидаемым сертификатом. Для поставки через Google Play отдельно проверяется подпись загружаемого AAB и схема Play App Signing. [Android Developers, подписание приложения](https://developer.android.com/studio/publish/app-signing) · [Android Developers, проверка APK](https://developer.android.com/tools/apksigner)

В отчёте о релизе каждая проверка получает дату, среду и итог «пройдена», «провалена» или «не выполнялась» с причиной. Для заявленной поддержки трёх живых каталогов требуется подтверждение всех трёх подключений. Сборка для тестирования с отключёнными источниками может фиксировать прогресс разработки отдельно от такого выпуска.

## Открытые проверки перед выпуском

- Проверить выдачу и карточки каждого источника с одобренными ключами. Подтвердить квоты, право хранения данных и допустимый срок для снимков. Настроить серверные лимиты расхода общей квоты.
- Проверить локальный LibreTranslate, Tesseract, точность и расположение перевода по OCR-блокам на реальных карточках.
- Проверить восстановление состояния WebView при повороте и остановке её процесса рендеринга на устройстве.
- Проверить отображение на разных диагоналях и при увеличенном шрифте во всех основных сценариях.
- Проверить контейнеры, восстановление PostgreSQL, GitHub Actions, подпись APK/AAB и развёртывание на Synology SA6400.
