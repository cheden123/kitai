# Как получить ключи Taobao, 1688 и Alibaba.com для Kitai

Каждую площадку можно подключить отдельно. Заявку подаёт владелец приложения. Опишите, как покупатель ищет товар в Kitai, сравнивает предложения и переходит к продавцу. Укажите, где будут видны названия, изображения и цены. До подключения подтвердите в кабинете право показывать эти данные вашей аудитории, доступные рынки, тариф и квоту.

## Taobao и Tmall

1. Войдите в Taobao Alliance со своим аккаунтом Taobao и зарегистрируйтесь как партнёр. В разделе **媒体备案** («регистрация канала») укажите тип **APP** и данные Kitai. Дождитесь одобрения канала. [Taobao Alliance](https://pub.alimama.com/) · [Инструкция по регистрации и правам](https://developer.alibaba.com/docs/doc.htm?articleId=118970&docType=1&treeId=713)
2. Нажмите **APPKEY申请** («запросить AppKey»), затем **新建应用** («создать приложение») и выберите одобренный канал. В управлении приложением откройте группы прав. Для зарубежного каталога Kitai использует `taobao.ovs.tbk.material.item.optional` для поиска, `taobao.ovs.tbk.material.item.info.get` для карточки и `taobao.ovs.tbk.material.item.link.convert` для создания ссылки, когда её нет в карточке. Подайте заявку на недостающие права. Эти три метода используют подпись приложения и допускают вызов без пользовательского OAuth. [Поиск](https://developer.alibaba.com/docs/api.htm?apiId=72807) · [Карточка](https://developer.alibaba.com/docs/api.htm?apiId=72811) · [Партнёрская ссылка](https://developer.alibaba.com/docs/api.htm?apiId=72803)
3. Скопируйте AppKey в `KITAI_TAOBAO_APP_KEY`, AppSecret — в `KITAI_TAOBAO_APP_SECRET`. В **推广管理 → 推广位管理** найдите или создайте место размещения для этого канала. В `KITAI_TAOBAO_ADZONE_ID` запишите последнее числовое поле PID. Например, из `mm_1_2_3` возьмите `3`. [Где найти adzone_id](https://developer.alibaba.com/docs/api.htm?apiId=64759)
4. В `KITAI_TAOBAO_SITE` укажите рынок программы. Поддерживаются `TW`, `HK`, `MY`, `SG`, `AU`, `CA`, `MO`, `GLOBAL`. Отдельного значения `RU` в справочнике нет. Для `GLOBAL` площадка пропускает проверку ограничений конкретного рынка, поэтому возможность доставки в Россию нужно уточнять у продавца. [Значения site](https://developer.alibaba.com/docs/api.htm?apiId=72807)

## 1688

1. Войдите в **控制中心** («центр управления») с аккаунтом 1688 или Taobao, прошедшим подтверждение личности. Для первого подключения подтвердите телефон и заполните профиль. В разделе **解决方案** («решения») выберите программу по своей роли. Для внешней закупочной системы с каталогом проверьте программу трансграничной ERP/SaaS. Вариант **自用** предназначен для собственной системы предприятия. Если кабинет запрашивает квалификацию, подайте **资质申请** и дождитесь решения. [Центр управления](https://open.1688.com/console) · [Руководство для новых разработчиков](https://aop.alibaba.com/doc/guide.htm) · [Назначение программ](https://aop.alibaba.com/doc/openIndex.htm)
2. В карточке решения проверьте права на `product.search.keywordQuery` и `product.search.queryProductDetail` в пространстве `com.alibaba.fenxiao.crossborder`, версия 1. При подключении решения создайте или выберите приложение. После одобрения откройте **进入应用开发** («к разработке приложения») и перенесите AppKey и AppSecret в `KITAI_1688_APP_KEY` и `KITAI_1688_APP_SECRET`. У обеих операций обязательны подпись и пользовательский токен. [Схема поиска и список решений](https://aop.alibaba.com/api/data/getApiDetail.json?namespace=com.alibaba.fenxiao.crossborder&name=product.search.keywordQuery&version=1) · [Схема карточки](https://aop.alibaba.com/api/data/getApiDetail.json?namespace=com.alibaba.fenxiao.crossborder&name=product.search.queryProductDetail&version=1)
3. Зарегистрируйте HTTPS-адрес возврата (`redirect_uri`) под контролем владельца. Откройте страницу авторизации 1688 по инструкции одобренного приложения. Пользователь разрешает доступ на сайте 1688, после чего площадка возвращает одноразовый `code` на этот адрес. Сразу обменяйте код на сервере через **HTTPS POST** к `system.oauth2.getToken` с теми же AppKey и `redirect_uri`, AppSecret и `grant_type=authorization_code`. В `KITAI_1688_ACCESS_TOKEN` запишите полученный `access_token`. Когда он истекает, используйте выданный `refresh_token` по правилам программы либо повторите авторизацию. [Метод getToken](https://aop.alibaba.com/api/data/getApiDetail.json?namespace=system.oauth2&name=getToken&version=1) · [Справка 1688 по авторизации и ошибкам](https://aop.alibaba.com/doc/docPage.htm?id=489289)
4. `KITAI_1688_OUT_MEMBER_ID` можно оставить пустым. Это внешний идентификатор пользователя (`outMemberId`), который Kitai передаёт при чтении карточки. Заполняйте его только при наличии соответствующего идентификатора по условиям программы. [Поля карточки](https://aop.alibaba.com/api/data/getModelInfo.json?namespace=com.alibaba.fenxiao.crossborder&apiname=product.search.queryProductDetail&version=1&type=1&typeName=product.search.queryProductDetail.param.OfferDetailParam)

## Alibaba.com

1. Откройте **Create Account** на портале Alibaba.com Open Platform, подтвердите почту и примите соглашение. После входа заполните **User ID → Profile** и приложите документы, которые запрашивает кабинет. Для закупочного сценария программе **Buyer Sourcing Solution** нужен действующий аккаунт покупателя Alibaba.com. [Портал разработчика](https://openapi.alibaba.com/) · [Регистрация](https://openapi.alibaba.com/doc/doc.htm#/?docId=51) · [Buyer Sourcing Solution](https://openapi.alibaba.com/doc/doc.htm#/?docId=96)
2. В **App Console → Create** запросите категорию приложения (**Apply**) и опишите закупочный сценарий в поле **Reason**. Если подходящей категории нет, обратитесь к команде портала через кабинет. После перехода категории в **Active** нажмите **Create App**, укажите имя и свой HTTPS callback. Откройте **Manage → App Overview** для App Key и **Basic Information → View** для App Secret. Перенесите значения в `KITAI_ALIBABA_APP_KEY` и `KITAI_ALIBABA_APP_SECRET`. [Создание приложения](https://openapi.alibaba.com/doc/doc.htm#/?docId=52) · [Где посмотреть ключи](https://openapi.alibaba.com/doc/doc.htm#/?docId=53)
3. В **App Overview → API Permission Group** найдите группы с `/eco/buyer/product/search` и `/eco/buyer/product/description`. Для группы в состоянии **Inactive** выберите **Apply**, укажите причину и дождитесь **Active**. Оба метода требуют `access_token`. [Запрос прав](https://openapi.alibaba.com/doc/doc.htm#/?docId=54) · [Поиск](https://openapi.alibaba.com/doc/api.htm#/api?cid=7&path=/eco/buyer/product/search&methodType=GET) · [Карточка](https://openapi.alibaba.com/doc/api.htm#/api?cid=7&path=/eco/buyer/product/description&methodType=GET)
4. По инструкции **Buyer ISV authorization** откройте `https://openapi-auth.alibaba.com/oauth/authorize` с параметрами `response_type=code`, `client_id` (App Key) и `redirect_uri` (зарегистрированный callback, закодированный как значение URL). В браузере покупатель входит в свой аккаунт и нажимает **Sign in And Authorize**. Сервер получает `code` и в течение 30 минут обменивает его подписанным вызовом `/auth/token/create`. Перенесите только `access_token` в `KITAI_ALIBABA_ACCESS_TOKEN`. Сохраните срок `expires_in` и, если выдан, `refresh_token` в защищённом хранилище владельца. При `refresh_expires_in > 0` используйте `/auth/token/refresh` до истечения срока и сохраните последнюю пару токенов. По истечении срока обновления потребуется новое согласие покупателя. [Авторизация покупателя и обновление токена](https://openapi.alibaba.com/doc/doc.htm#/?docId=99)

## Где хранить значения и как проверить доступ

Для Docker Compose при первом развёртывании создайте `deploy/kitai.env` из шаблона. Если файл уже существует, добавьте в него значения выбранной площадки. Секреты площадок и токены OAuth храните только на сервере. В Android вводится отдельный `KITAI_API_TOKEN` для доступа к своему серверу. Текущая версия Kitai читает готовые токены при запуске. Обработчик OAuth callback, обмен и обновление выполняются вне Kitai. После замены значений пересоздайте сервис `api` с теми же файлами Compose, с которыми он запущен. Для базовой конфигурации команда из корня проекта — `docker compose -f deploy/compose.yaml up -d --force-recreate api`. [Шаблон переменных](../../deploy/kitai.env.example) · [Развёртывание](../../README.md)

Для 1688 и Alibaba.com сервер использует по одному токену на площадку. Уточните при одобрении, разрешён ли этот режим для вашей аудитории. Если программа требует отдельного согласия каждого покупателя, для многопользовательского запуска потребуется авторизация и хранение токенов по пользователям.

Для проверки откройте PowerShell на сервере. Передайте `KITAI_API_TOKEN` в окружение текущего процесса из своего хранилища секретов. Выберите `taobao`, `1688` или `alibaba` и выполните один поиск и чтение карточки. Для удалённого подключения укажите HTTPS-адрес своего сервера.

```powershell
$base = 'http://127.0.0.1:8000'
$source = '1688'
$headers = @{ Authorization = "Bearer $env:KITAI_API_TOKEN" }
(Invoke-RestMethod "$base/api/v1/sources" -Headers $headers).sources |
    Select-Object id, status
$query = if ($source -eq 'alibaba') { 'stainless steel thermos' } else { '保温杯' }
$encoded = [uri]::EscapeDataString($query)
$page = Invoke-RestMethod "$base/api/v1/search?source=$source&q=$encoded&limit=1" -Headers $headers
$page.sources | Select-Object id, status
if ($page.items.Count -gt 0) {
    $id = [uri]::EscapeDataString([string]$page.items[0].id)
    Invoke-RestMethod "$base/api/v1/products/$source/$id" -Headers $headers |
        Select-Object id, source, title, url
}
```

Сразу после запуска статус `configured` означает, что Kitai распознал настройки. Подтверждением доступа к каталогу служат статус поиска `available` и возвращённая карточка с тем же ID. При пустом ответе `available` попробуйте другой запрос. Статус `not_configured` указывает на неполные или неподходящие настройки, `forbidden` — на отказ в доступе, `rate_limited` — на ограничение частоты, `unavailable` — на другую ошибку источника. Ответ самого Kitai `401 authentication_required` требует проверки `KITAI_API_TOKEN`. Справочники и код сверены 24 ноября 2026 года. Реальная выдача зависит от личного одобрения и проверяется с выданными владельцу ключами.
